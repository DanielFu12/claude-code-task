# 护城河系列视频 · 制作规则与经验

> 来源：《便宜≠护城河：低成本成为护城河的三个条件》（`低价护城河/`）从 v1（3:02）到 v5 的五轮迭代（v4/v5 解决旁白音色一致性，v5 加入版面自动审计和文字清晰度规则）。
> 用途：基于本分支制作**护城河系列**（品牌、网络效应、转换成本、规模、牌照、定价权……）的新一期时，先通读本文和分期表 `护城河系列规划.md`，再从 `低价护城河/` 复制工程起步。
> 系列已完成：第 01 期《社会地位象征型护城河》（`地位护城河视频/`，早于本规则制作，横屏无配音）、第 02 期《便宜≠护城河》（`低价护城河/`，本规则的来源）。
> 规则分两类：**必须**（踩过坑、有明确后果）和**建议**（做过验证、效果好）。

## 〇、开工前先做的五件事

1. 读本文 + `brand/BRAND.md` + `低价护城河/README.md`（结构表）+ `低价护城河/docs/核实笔记.md`（核查的颗粒度示例）。
2. 复制工程：`cp -r 低价护城河 <新一期目录>`，删掉旧成片、`work/`；**引擎、旁白、混音模块原样复用**，只改 `script.py`、`timeline.py` 的 `CHAPTERS`、`music.py` 的时刻表、`video.py`（竖版）和 `video_h.py`（横版）的场景函数，以及 `build.sh` 里导出视频脚本那一行的编号和片名。
3. 确认旁白可用：`python3 src/tts.py "测试" /tmp/t.mp3`（见第五节）。
4. 确认素材通道：Wikimedia Commons、archive.org 可达（见第四节）。
5. 先写脚本、做事实核查、做逻辑审查（第一～三节），**脚本定稿前不要动画面**——改一句话，后面整条时间线都会移动。

## 一、选题与叙事：用第一性原理搭骨架

### 1. 已验证有效的结构（约 6 分钟）

| 段落 | 作用 | 本期做法 |
|---|---|---|
| 引子 · 现实经济现象 | 从观众身边的事讲起，制造“为什么” | 光伏跌破成本线、汽车价格战、外卖 0 元购 → 越卖越亏 → 政策文件 → “价格战打到最后，谁建起了护城河？” |
| 反差钩子 | 两个结局相反的案例 | Costco 热狗 40 年 1.5 美元 vs ofo 一千多万人排队退押金 |
| 片名 | **结论式标题** | 便宜 ≠ 护城河｜低成本成为护城河的三个条件 |
| 01 第一性原理 | 拆到不可再拆的公式 | 利润 = 价格 − 成本；价格是决定，成本是结构 |
| 02 大师对撞与调和 | 制造认知冲突，再用原话调和 | 巴菲特“低成本生产者是屏障” vs 段永平“没见过成本优势成护城河” → 段永平自己说“GEICO、Costco 靠的是商业模式”“护城河≈定价权” |
| 03 成立条件 | 给出可操作的框架 | 结构性 / 可持续 / 可转化，每条配一个正例、一个反例 |
| 04 中国考题 | 用框架给中国公司“体检” | 比亚迪、拼多多：✓ / ? / ×，**不下结论** |
| 05 底线 | 反方向的失败模式 | 偷工减料 → 飞轮倒转 |
| 06 答案 | 回到标题，一句话收束 | 低价是选择，低成本是能力，把能力变成定价权，才是护城河 |
| 片尾 | 品牌动画 | 见第九节 |

### 2. 标题规则
- **必须**：标题本身就是第一性原理的结论，并且与正文结论一字不差地一致（片中最后一章要回到标题）。
- 建议格式：`<反常识判断>｜<成立条件/机制>`。如“便宜≠护城河｜低成本成为护城河的三个条件”。
- 区分“现象词”和“机制词”：低价格（决定，谁都能做）≠ 低成本（结构，难复制）。系列里其他护城河同理：广告声量 ≠ 品牌，用户多 ≠ 网络效应，签了合同 ≠ 转换成本。

### 3. 引子规则
- 从**当下真实的经济现象**慢慢展开，再明确区分“现象”与“护城河”（本期：内卷式低价 vs 护城河）。
- **必须核对时间口径**：v2 准备写“PPI 持续为负”，核查发现 2026-10 PPI 同比已 +5.7%，于是改成“过去几年”。不要把旧数据说成“当前”。
- 片尾**不要**做评论区互动（“评论区聊聊”等），收在结论金句 + 品牌动画上。

## 二、逻辑一致性审查（定稿前逐句过两遍）

本期第三轮在已发布的脚本里一口气找出 11 处矛盾。以下是归纳出的**十类常见错误**，每一类都附本期实例：

| # | 错误类型 | 本期实例（原句 → 改为） |
|---|---|---|
| 1 | **与紧接着的论据矛盾** | “内卷，就是没人动得了成本” → 但下一段芒格织布机讲的正是大家都在降成本 → “大家都在降价，彼此的成本却拉不开差距” |
| 2 | **“只有一个” vs 后文多个** | “真正的检验只有一个” → 后面讲三个条件 → “第一道检验是” |
| 3 | **与自己引用的大师原话冲突** | “低成本不是城墙本身” vs 巴菲特“低成本生产者是屏障” → “低成本是燃料，它换来的东西，才是城墙” |
| 4 | **特例当通则** | “商品不涨价”（只有热狗 40 年没涨）→ “商品坚持薄利” |
| 5 | **结论措辞推翻前文** | “定价权才是护城河” 听起来否定了“低成本可以成为护城河” → “把能力变成定价权，才是护城河” |
| 6 | **转折词没有转折对象** | 提问后接“可也有人……” → “有人……” |
| 7 | **措辞暗示与片名相反** | “同样是便宜，一个成了护城河” 暗示便宜=护城河 → “一家筑起了护城河，一家走进了坟墓” |
| 8 | **引文意译偏离原文** | 巴菲特 irrational 译成“毫无意义” → “反而不理性” |
| 9 | **漏掉原话的前提** | 芒格的织布机说的是 commodity 生意 → 补“在纺织这种同质化的生意里” |
| 10 | **以偏概全** | “只会降价的行业” → 同一行业里也有成本领先者 → “只会降价的公司” |

审查方法：
- 把全文打印成一行一句（`python3 -c "from script import LINES; ..."`），**逐句问三个问题**：这句和前一句、后一句、片名是否冲突？这句有没有“只/都/从来/不是……而是”这类绝对词，绝对得成立吗？这句引的原话，原文前提是什么？
- **改了脚本，画面上的同义文字也要同步改**（本期改了旁白，屏幕上的芒格引语卡、“只会降价的行业”标题都还是旧词，第二遍才发现）。
- 发布文案、README 里的同一句话也要同步。

## 三、事实核查规则

- **必须**：片中每个数字、每句引语都要有可追溯来源，记入 `docs/核实笔记.md`（表格：片中说法 / 核实结果 / 来源与口径）。
- 公司未正式披露、只有媒体报道的数字：旁白说“据多家媒体报道”，屏幕标“据报道”（如 Costco 加价 ≤14%）。
- 自己算出来的数字写清口径（如会员费 59.07 亿 ÷ 经营利润约 116.85 亿 ≈ 50.6%）。
- **引语**：只用能找到原文或多个独立整理稿一致的；找不到原帖的**不用**，换成已核实的同义原话（本期“能涨价的东西就表示他有护城河”核不到，改用“护城河可以简单理解为定价权”）。屏幕标出处与场合（如“段永平，2010，答网友：比亚迪的成本优势是不是护城河”；口语整理稿标“据 2018 年斯坦福交流整理”）。
- **有争议的公司**（比亚迪、拼多多等）：只陈述可核实的事实，并**同时给出公司回应**（“比亚迪回应：行业惯例，可协商”）；用“体检表 ✓ / ? / ×”呈现，**不下“压榨”“违法”之类的结论**，把判断留给观众。
- 数字读法：配音文本写口语（“一千多万”“四百六十万”“百分之十四”），字幕文本保留阿拉伯数字。两者在 `script.py` 里分开写。
- 网络检索：WebSearch 可用；sohu / zhihu / huxiu / 雪球 PDF 等页面本环境**抓取不到**，用多次检索结果交叉核对代替。

## 四、素材

- **Wikimedia Commons**（首选，许可清楚）：
  - 请求必须带描述性 User-Agent；检索间隔 ≥8 秒，否则 429。
  - 直接拉原图会触发 “robot policy” 429；改用**标准缩略图宽度 1920**（`/thumb/<a>/<ab>/<name>/1920px-<name>`；1600、2560 不是标准宽度，会 400）。
  - 检索结果里的 URL 带 `?utm_...` 参数，**拼缩略图前先去掉**。
  - 每张图写入 `media/credits.json`（作者、许可、页面），片中用 `credit()` 标注；CC BY-SA 必须署名。
- **archive.org**：元数据可读；下载走 `iaXXXXXX.us.archive.org` 数据节点，需要在网络白名单里（本环境已加了一批）。ffmpeg 可以直接 `-ss` 远程截取片段，不用下载整片。新闻档案片段只截 ≤6 秒作评论引用。
- **必须**：没有某公司的图，就用纯色底 + 示意图，**不要拿别家的照片冒充**（本期拼多多段落一度临时用了 Costco 卖场图，已改掉）。
- 没有开放授权照片的人物（如段永平）：用排印面板（大字“段” + 姓名 + 英文名），不要找来源不明的照片。
- 好用的公有领域素材：Lewis Hine 的工厂照片（美国国会图书馆）、NASA Earth Observatory 卫星图、美国政府机构照片（巴菲特 2015 SelectUSA）。

## 五、旁白（豆包 Seed-TTS 3.0）

- 接口：`https://voice.cn-beijing.volces.com/api/v3/text-to-speech/<voice>/streaming`，`model_id: doubao-seed-tts-3.0`，`enable_subtitle: true` 返回**逐字时间戳**。API Key 由环境网络代理注入（`X-Api-Key`），代码里写占位值即可。
- 音色：`multi_male_liufei2_v3_uranus_bigtts`（系列统一使用）。
- 参数：`voice_settings.speed` 有效（本期 1.15，实测约 6.0 字/秒）；`instructions`、`context_texts` 等语气提示**无效**，节奏靠标点和断句控制。
- **整篇一次合成（单条录音，没有接缝）+ 多条候选择优 + 只修残余小漂移**（`src/tts_single.py`）。这是第 02 期 v5 定下的做法：
  - 背景：v3 整篇一次合成后用 PSOLA 把音高大幅拉平（修正 5 个半音以上），后段发糙；v4 改成分段合成 + 择优，各项指标都好，但用户仍听出“音色不一致”——每段都是一次新的“表演”，段与段的语气状态不同，数值指标测不出来。**结论：整条录音的语流连贯最重要，用户偏好一次合成。**
  - Seed-TTS 长录音会系统性越讲越高：第 02 期 6 条完整录音全部上爬 +0.5～+0.75 半音/分钟，第一分钟之后谐噪比也都略降。漂移程度每条不同，所以**一次合成 6 条，选 60 秒窗音高范围最小、斜率最小的一条**（第 02 期选中的一条：范围 2.6 半音、+0.5 半音/分）。
  - 残余漂移按逐句音高的 ±40 秒趋势做 PSOLA 平滑修正，**单点修正上限 2 个半音**（小幅修正不损音质；v3 的问题出在修正量过大）。修正后第 02 期：60 秒窗范围 1.55 半音、斜率 +0.18 半音/分，谐噪比与修正前一致。响度按 ±40 秒趋势慢速拉平（±2 dB 内）。
  - `voice_settings.speed` 有效；`voice_settings.pitch` 也有效（+6 ≈ +5.4 半音，模型内部升降调，比后期移调干净），但只能整体偏移，不能纠正同一条录音里的漂移。speed 1.0 漂移略小（+0.38～+0.66 半音/分），但片长多约 50 秒，第 02 期仍用 1.15。
  - 并发不超过 2，每条候选检查时间戳覆盖 ≥97%、时长合理，否则重新请求。
  - 备用方案：`src/tts_chunks.py`（分段合成 + 候选择优 + 动态规划保证接缝连贯）。数值上一致性最好，但段与段的语气状态有差别，**只在整篇合成无法达标时使用**。
- **验收**：`src/voice_qc_single.py`（逐句 Praat 音高 → 60 秒窗中位数；斜率；窗响度；每分钟谐噪比）。标准：60 秒窗音高范围 ≤ 约 1.6 半音、斜率 ≤ 0.2 半音/分、窗响度范围 ≤ 1 dB。不要在拼起来的长音频上用三法一致估计做验收（个别段会跟踪漂移）。
- **最后必须人耳通听一遍**：自动指标只能发现数值问题，“像不像同一个人在一口气讲”只能靠听。
- 切句：按逐字时间戳，在两句之间停顿的能量最低点下刀；`vo.json` 里每个文本位置都有时间（标点取上一字结束时刻），`WT(句, '词')` 由此取某个词的发声时刻。
- 每次改稿都会重新合成受影响的段（按文本哈希缓存），语速、停顿会有自然波动，**改稿后必须重跑 `voice_qc.py`，并检查时长和所有 `WT` 关键词是否还在**。

## 六、字幕

- 按标点切短句，每屏 ≤16 字（数字、`.`、`%` 按 0.55 字宽计）；超长自动缩字号。
- 句首 ≤4 字的短语（“2025年，”）并入后一句，不单独成屏。
- 相邻字幕**不能重叠**：每条在下一条出现前 0.05 秒收掉，淡入淡出不交叠（本期第一版有一帧重影）。
- 屏幕上已有同句大字时（片名问句、结尾金句、引语卡），把该句加入 `NOSUB`，避免同一句话出现两遍。

## 七、画面（1080×1920 竖屏 + 1920×1080 横版）

- **每一期都要交付竖版和横版两个成片**（2026-11 起）。两版共用同一条旁白、配乐、混音和时间线（`work/mix.wav`、`hits.json`），只有画面不同：竖版 `src/video.py` + `build.sh`，横版 `src/video_h.py` + `build_h.sh`，成片文件名加“_横版”。
- 横版不是把竖版缩小或加黑边：字号会降到清晰度规则以下，两侧也是空的。每个场景按 16:9 重新构图：照片 / 视频铺满全屏或占左半（16:9 素材在横版里直接满屏），标题、数字、图表放右半或中轴；字幕中心 y≈960，底部同样留安全区；右上角角标用 `Hud(frame_w=1920)`。横版同样要跑版面审计到 0 处。

- 竖版版面：右上角品牌角标（`Hud(scale=1.0, frame_w=1080)`）；左上章节标签（中文 + 英文小字）；主体 y≈220–1300；字幕中心 y≈1470；底部留给平台 UI。
- 视觉语言（系列统一）：深色底 + 金色（护城河/正面）+ 红色（失血/内卷）+ 青色（盈利/✓）+ 冷蓝（成本/中性）；暗角、轻颗粒、bloom。
- **每个元素的出现时刻绑定到旁白的某个词**（`WT(句, '词')`），不要写死秒数；打字机式引文要在该句 60–80% 处打完，否则会落后于旁白。
- 字体坑：
  - Oswald 没有中文：“460 万辆”“275 天”要把数字和中文单位**分开渲染**。
  - 中文字体没有 ✗：用 ×。✓ 可以显示。
  - `cv2.line` 零长度会画出一个点：`line()` 里已跳过。
- **版面必须做自动审计，不要只靠抽帧目测**（第 02 期 1:10 的文字压积木就是抽帧漏掉的）：`python3 src/video.py WORK audit t0 t1 0.2 out.json`（4 进程分段并行约 6 分钟）+ `python3 src/layout_audit.py out*.json`。
  审计记录每段文字的字形像素和每张卡片的范围，并把描边图形（线、弧、圆环、点）累积成掩膜；不透明填充会遮住其下的线条，`dim()` 压暗会同步降低记录的可见度。报出：两段可见文字重叠、文字跨在卡片边上、文字字形压在线条/图形上（≥60 像素或 ≥0.8%）、文字出界。删除线等有意的叠加写进白名单。
  常见成因：标签跟着曲线末端走（改成固定位置图例）；说明文字放在积木/柱子附近（放到标题行或图例行）；数据标签与参考线同高（放进柱子中段）；转场时上一段内容没淡完下一段就出来（先淡出再淡入）；两条数据挤在同一时间轴（拆成两行、各用自己的时间轴）；圆环/光环半径小于里面文字的半宽。
  **整体压暗画面一律用 `dim(cv, f)`，不要直接 `cv *= f`**，否则审计会把已经看不见的文字当成可见。
- **文字清晰度**（第 02 期 v5）：文字写入字形掩膜，`finish()` 在字形上不加颗粒、不参与泛光（泛光会给字边加一圈雾）；颗粒强度 0.012；细体（Light）在 36px 以下自动改中等字重、任何文字不小于 24px；深色字（浅色卡片上）不加阴影（否则字边一圈灰晕显得糊）；标题的金色光晕用文字自带的 glow，不依赖全局泛光。编码加 `-tune animation`（同码率下主画面 PSNR +1.45 dB）；预览版 CRF 24。
- 每改一批场景就抽帧拼图检查（`src/video.py WORK still t1 t2 ...` + `src/sheet.py`），重点看：叠字、元素被遮挡、空镜头太久、文字超出安全区。
- 场景函数按“段落”划分，章节内子画面用旁白句首切换；场景之间 0.45 秒交叉溶解，进片尾 1.0 秒。

## 八、配乐与混音

- 程序作曲（MIDI → FluidSynth + FluidR3 GM），80 BPM（每拍 0.75 秒），D 小调为主，结论段转 D 大调；章节句首对齐节拍网格。
- 重拍全部取自旁白发声时刻（片名、对撞、每个条件、会合、“这就是内卷”、“值不值”、片尾），写进 `hits.json` 给画面共用，**声画天然同步**。
- 不用镲片和高频扫频；转场只用低频轰鸣、弦乐渐强、低通气声。
- 配乐先做慢速电平均衡（3 秒窗 2:1）再归一到 −18 LUFS，否则低频冲击把峰值归一化拉低，整首太轻（v1 片名处只有 −23 LUFS）。
- 混音：旁白 −17 LUFS 处理后与配乐合并；有声处配乐 −11 dB 闪避；整体 −14 LUFS，真峰 −1.2 dBTP。
- **片尾重拍不能比旁白响**：用 3 秒窗短时响度检查，本期主重拍原本 −11 LUFS（比旁白高 3 LU），已在 logo 落定后配乐 −3.5 dB。
- 交付前检查：全片 3 秒窗短时响度（无 < −30 LUFS 的死寂段）、句间最长停顿（只应出现在片名、章节转场）。

## 九、片尾品牌动画（系列统一规格）

约 11 秒（`timeline.py` 里 `OUTRO = 12.0`），时间点全部对齐节拍并写进 `hits.json`：

1. **汇聚**（`logo` → `logo_land`，约 2.25 秒）：最后一句金句的字形化作约 3200 颗金色粒子（85% 取自字形，15% 取自全屏尘埃），沿旋转弧线汇聚到 logo 像素位置；飞行时保持金色，接近落点（缓动³）才变成 logo 的蓝色。配乐：弦乐渐强 + 钢片琴上行（不超过 F#6）。
2. **落定**（`logo_land`）：清晰 logo 居中浮现（340px，y=720），淡蓝柔光（alpha 先 pad 再模糊，否则有方形边）+ 一圈扩散光环；配乐：定音鼓 + 低频。
3. **重拍落字**（`brand` = 落定后 2 拍）：金色「巴芒价值」（Noto Serif SC Black 118px）缩放落下并扫过一道斜向流光；0.25 秒后「BUFFETT · MUNGER」（与主标题等宽）带流光出现；文字后方只加一点径向暖光，不要整屏闪色。
4. **关注语**（`slogan` = 再 3 拍）：一条细金线从中心向两侧展开，引出两行“关注「巴芒价值」”“传承大师智慧，领悟投资真谛”，逐行上浮淡入；配乐：竖琴 + 钢琴主题。
5. **淡出**（最后 1.8 秒）：整体淡到黑，配乐同步淡出。

实现见 `低价护城河/src/video.py` 的 `Gather` 类和 `sc_end()`；新一期只需把粒子起点换成本期最后一句金句的字形。

## 十、渲染与交付

- **必须**：每个渲染进程单线程（`cv2.setNumThreads(1)`，`OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1`），否则 4 核机器负载 16，速度掉一半以上。4 进程并行分段渲染，约 1.2–1.7 帧/秒/进程，6 分钟片约 35 分钟。
- **必须**：`build.sh` 运行期间不要改它（bash 边读边执行，改了会从错位的字节继续跑）。需要改码率等，等它跑完再单独重编码。
- 先出 CRF 20 母版（`work/master_crf20.mp4`），再两遍编码出成片。
- **仓库 Git LFS 额度已满**：新目录放一个 `.gitattributes`，写 `*.mp4 -filter binary`，成片按普通文件入库；GitHub 单文件上限 100MB，**成片控制在 95MB 内**。码率估算：视频码率 ≈ 95MB×8 ÷ 时长 − 音频码率（6 分钟约 1.85 Mbps）。用 SSIM 对比母版验收（本期 0.989）。颗粒会吃码率，低码率时把颗粒强度降到 0.016。
- **交付物（2026-11 起）**：每期只出两个成片——竖版 `<片名>.mp4`（`build.sh`）和横版 `<片名>_横版.mp4`（`build_h.sh`），**不出预览版**；两个都控制在 95MB 内（横竖像素数相同，同码率大小几乎一样）。
- **视频脚本单独存档**：每期的定稿旁白导出到仓库根目录 `视频脚本/<编号>_<片名>.md`（章节时间、逐句时间码、字幕文本与配音读法、连读全文），由 `python3 ../视频脚本/export_script.py . <编号> "<片名>"` 生成，写在 `build.sh` 的 `timeline.py` 之后，每次重建自动更新；改稿后必须重新导出并提交。
- 提交时**只 add 具体文件**，不要 `git add <整个目录>`——渲染中途会把半成品或旧成片带进去（本期 v1 就误提交过一个 416MB 的文件，LFS 推送失败后撤回）。
- 根目录三个历史 mp4 一直显示“已修改”（LFS 规范化导致），**不要提交**：提交会变成 LFS 指针，而 LFS 额度已满，真实文件传不上去。
