# 旁白：全片语气一致、分段衔接自然、没有 AI 味

> 来源：《好公司，为什么还会亏？》（`伪价值投资视频/`）从 V1 到 V10 的配音迭代。
> 前九版都在「逐句 / 逐段合成，再用后期去补」的思路里打转，衔接处始终能听出换了一口气、换了一个人；
> V10 改成**整篇一次合成**，问题才从根上消失。下面按「结论 → 做法 → 参数 → 自检 → 踩过的坑」整理，下次直接照做。
>
> 注：`伪价值投资视频/` 不在本仓库，文中的文件路径指那个项目的源码，供对照；本仓库的「巴芒价值」各期按本文做法改造时，在各期 `src/` 里实现。

## 一、核心结论（先记住这五条）

1. **整篇旁白一次合成，一条录完。** 每一次 TTS 请求都会重新「起一口气」：音高、能量、语速、音色都从头开始。
   只要分成多次请求，接缝就一定听得出来，后期移调、均衡、加混响都补不回来。
   Seed-TTS 2.0 实测：3115 字一次请求，约 2 分钟返回 8 分 45 秒音频，没有问题。
2. **切句靠对齐，不靠猜停顿。** 语速一快，句间停顿只有 0.11–0.15 秒，和句内逗号停顿一样长，按停顿切必然切错。
   用「逐句参考音频 + 子序列 DTW」逐句定位句界，再在停顿正中下刀。
3. **段内不插人为停顿。** 切开的句子首尾相接放回去，就还原成原来那一条录音；
   只在章节卡、小节转场这类「本来就该停」的地方加停顿。为了卡点挪动时间，只允许在已有停顿里挪，最多 ±0.19 秒。
4. **长文本会越讲越高，要拉平。** 一次合成 8 分钟，音高中位数会从约 110 Hz 慢慢爬到 145–165 Hz（首尾差约 3.7 个半音），
   听感是越来越紧、越来越激动。只拉平缓慢趋势（±25 秒滑动中位数），逐句的抑扬顿挫不动。
5. **局部调速用时长变换，不用改请求参数。** 某一章要慢下来，用 Praat 的 PSOLA 把那几句拉长（不改音高），
   而不是单独再请求一次——单独请求就又多出两条接缝。

## 二、标准做法（流水线）

参考实现：`伪价值投资视频/src/tts_all.py`、`tts_take.py`、`timeline.py`、`mix.py`、`voice_check.py`。

```
脚本.md ──gen_script.py──▶ script.py（配音文本：数字转口语读法；字幕文本：保留阿拉伯数字）
        │
        ├─ tts_all.py   逐句合成「参考音频」work/vo_ref/（同音色、同语速、同语气提示）——只用于对齐和校验，不进成片
        │
        └─ tts_take.py  ① 整篇一次合成 → work/vo_take/take_<hash>.mp3
                        ② 拉平音高漂移（pYIN 估趋势 + Praat PSOLA 改音高点）
                        ③ 逐句对齐切句：本句参考 + 下句开头 1.5 秒，与录音窗口做子序列 DTW → 句界 → 吸附到停顿正中
                        ④ 逐句校验（不过就整条重录）
                        ⑤ 整条只做一个增益（有声部分 RMS → -20 dBFS）
                        ⑥ 指定章节用 PSOLA 拉长
                        ⑦ 输出 work/vo/Lxx.wav + gaps.json（标记哪些句子与上一句首尾相接）
timeline.py  段内首尾相接；只在章节 / 小节开头留白、对齐网格；揭晓点只在停顿里挪 ≤0.19 秒；少数句后加「讲故事的停顿」
mix.py       配乐闪避放在最后一步（压缩之后）
```

### 1. 语气提示（Seed-TTS 2.0 的 `additions.context_texts`）

整篇只用**一条**语气提示，具体到人物、场景和情绪走向，并明确要求「全程同一个人、同一种状态」：

> 你是一位经历过牛熊、亏过也赚过的老投资人，在深夜跟一位刚被套牢的朋友掏心窝子聊天：情绪真实饱满，讲到亏损时有惋惜，讲到转折时语气一顿再加重，讲到结论时笃定有力；口语化，有呼吸感，不播音腔，语速偏快、干脆利落，全程同一个人、同一种状态

- 「像在和朋友慢慢聊天、语速适中」这类平淡提示 → 听众反馈「慢、没感情、容易睡着」。
- 提示词里写「不要越讲越高」并不能消除长文本的音高漂移（三种写法实测首尾都升高 2–4 个半音），漂移要靠后期拉平。

### 2. 语速

| `speech_rate` | 实测语速（含停顿） | 结论 |
|---|---|---|
| 6 | 约 4.5 字/秒 | 偏慢，听众说「容易睡着」 |
| 25 | 约 5.3 字/秒 | **全片基准**，讲故事、讲道理都合适 |
| 32 | 约 5.6 字/秒 | 讲概念的章节（如「价值投资的本质」）听众觉得太快 |
| 40 | 约 6.0 字/秒 | 太赶，音高起伏也变小 |

- 不同内容要不同语速，但**不要分开请求**：整篇按 25 合成，概念密集的章节用 PSOLA 拉长 1.2 倍、句后多留 0.45–1.6 秒；尾声拉长 1.05 倍。
- 「讲故事的停顿」：关键句之后（如「你不甘心。」「未必。」、每个案例亏损数字落地后）多停 0.9–1.3 秒，比整体放慢更有效。

### 3. 拉平音高漂移（`detrend_pitch`）

- 趋势用 **pYIN** 估：`librosa.pyin(fmin=60, fmax=300)`，有声帧换成半音，±25 秒滑动中位数。
  **不要用 Praat 自带音高点估趋势**：它有倍频错误，估出来的趋势偏低，第一次只修掉了一半漂移。
- 修正：Praat `To Manipulation` → 取音高点 → 每个点乘 `2^(-0.9 × 趋势/12)`（目标 128 Hz，修 90%）→ `Get resynthesis (overlap-add)`。
- PSOLA 保留共振峰，音色不变；实测谐噪比 8.7 → 9.9 dB，没有变差。
- 结果：每分钟音高中位数 124–129 Hz（原来 111→146 Hz），音高起伏 4.5 → 4.1 个半音，抑扬基本保留。

### 4. 逐句对齐切句（`align` / `check`）

- 特征：16 kHz MFCC（20 维去掉第 0 维，逐维标准化），帧长 20 ms，余弦距离。
- 逐句推进：窗口 = `[当前位置 − 0.4 秒, 当前位置 + 1.6 × 本句参考时长 + 3 秒]`；
  模板 = 本句参考 + 下句参考开头 1.5 秒（让句界两侧都被约束）；`librosa.sequence.dtw(..., subseq=True)`。
- 吸附：句界 ±0.35 秒内的停顿里，选「够长、离估计点近」的那个，在**停顿正中**切；没有停顿就取能量最低点。
- 校验（每一句都要过，否则整条重录）：
  - 切出来的这一句，与本句参考的 DTW 距离，要比与上一句、下一句参考的距离都小（至少小 2%）；
  - 时长比（切出 / 参考）在 0.7–1.4 之间。
- 整段长音频不能直接做一次全局 DTW（8 分钟 × 8 分钟的代价矩阵太大），必须逐句推进。

### 5. 时间轴（`timeline.py`）

- `gaps.json` 里不是 `null` 的句子，表示与上一句首尾相接：`t_next = t + d`，**不插停顿、不对齐网格**；
  这些句子里开始的小节，画面跟着话走，小节起点在揭晓对齐**之后**再定。
- 只有 `BREAKS`（章节卡、片名、小节转场）前才留白并对齐小节线；小节转场不要额外加拍，留白控制在 1–3 秒，否则像「冷场」。
- 数字揭晓：只在已有停顿里挪动 ≤0.19 秒对齐半拍；金句前可多留半口气（对齐整拍，最多 0.6 秒）；
  连续重击（如三锤）按半小节的整数倍间隔，放得下上一句即可。

### 6. 混音（`mix.py`）

- 闪避必须放在**最终混音、压缩器之后**。放在配乐渲染里、压缩之前，会被母带压缩和动态 loudnorm 抹平，
  标称压 7 dB，实际听感几乎没压。
- 参数：人声时全频 −12 dB，人声频段（700 Hz–4 kHz）再 −5 dB；提前 0.15 秒开始压，保持 0.9 秒（句间短停顿不放开），
  起 80 ms、放 550 ms。实测说话时旁白比配乐高约 16 LU。
- 响度：线性增益到 −14 LUFS + 峰值限制，不用动态 loudnorm。
- 旁白本身：70 Hz 高通、2.2:1 轻压缩、很淡的同一个小房间短混响（RT60 约 0.6 秒，湿声 0.1）、−64 dBFS 粉噪底，
  把录音「放进同一个房间」，句间不是数字静音。

### 7. 字幕

- 句子首尾相接后，「每条字幕结束后多留 0.25 秒」会让两条字幕叠在一起（V9 出现过 205 处）。
  规则：每条字幕在下一条出现前 0.1 秒收掉。

## 三、自检清单（交付前必须跑，不能只靠「听起来还行」）

1. **对齐校验**：`tts_take.py` 打印 `alignment check failures: none` 才算过。
2. **音高漂移**：每分钟音高中位数，首尾差应 < 1 个半音（V10：124–129 Hz）。
3. **逐句报告**：`python3 src/voice_check.py work`，看
   - 各章语速（有声部分）：讲故事的章节约 7.2–7.4 字/秒，讲概念的章节明显更慢（V10 第三章 6.3）；
   - 各章音高中位数相差 < 1.5 个半音（V10：119–127 Hz）；
   - 相邻句的音高、响度、亮度跳变：在一条录音里，跳变只来自正常语调；如果跳变集中出现在 `BREAKS` 处，说明接缝有问题。
4. **谐噪比**：后期处理前后各测一段，不能变差。
5. **听**：自动指标只能发现数值问题。交付时要请人专门听章节转场处，有问题按时间码定点修。

## 四、踩过的坑（按时间顺序）

| 版本 | 做法 | 结果 / 教训 |
|---|---|---|
| V1–V7 | 逐句合成，每句单独响度归一 | 每句音高、音色各自起落，像几个人轮流念；响度归一只能对齐音量，对齐不了音色 |
| V7 | 统一语气提示 + 逐句响度归一 | 有改善，但段落之间仍明显「换了一口气」 |
| V8 | 按段整段合成（31 段 → 41 段），后期 PSOLA 移调、长时平均频谱均衡、统一混响底噪 | 段内自然了，段与段接缝仍听得出；后期只能对齐平均音高和音色，对齐不了「重新起一口气」的韵律 |
| V8 | 按停顿 + 动态规划切句 | 语速一快，句间停顿和逗号停顿一样短，大段落切句失败，回退成小段，接缝反而更多 |
| V9 | 按章合成（8 段）+ DTW 强制对齐，提速到 32、情绪更饱满 | 接缝少了但仍在（如「可新的问题来了」处明显变声）；第三章太快 |
| V9 | 句子首尾相接后，字幕仍按「句末多留 0.25 秒」 | 两条字幕叠在一起 |
| V10 | **整篇一次合成** + 拉平音高漂移 + 逐句子序列 DTW 切句 + 第三章 PSOLA 放慢 | 全片一条录音，没有接缝；音高 124–129 Hz 稳定 |

其他教训：

- **脚本本身的问题，配音救不回来。** 病句、指代不明、把假设说成事实、一句话里堆四个数字，听众第一遍就听不懂。
  合成前逐句审校，例子只用一个对象、一组数字（V10 审校表见 `伪价值投资视频/脚本.md` 文末）。
- 数字按口语读法送进 TTS（「二零一八年」「三百七十多」「一千五」），字幕仍显示阿拉伯数字。
- Seed-TTS 2.0（`X-Api-Resource-Id: seed-tts-2.0`）开 `enable_timestamp` 也**不返回**逐字时间戳，切句只能靠对齐。
- 接口偶尔 502，重试即可；整篇请求按文本 + 语气 + 语速做哈希缓存，避免重复请求。
- 改正在运行的 `build.sh` 会让 bash 从错位的字节偏移继续读，构建会坏掉——渲染期间不要改它。

## 五、第八期（内布拉斯加家具城）补充：在「巴芒价值」系列上落地时遇到的问题

实现：`内布拉斯加家具城/src/tts_take.py`、`voice_build.py`、`timeline.py`、`audio_mix.py`、`check_vo.py`。

| 问题 | 做法 |
|---|---|
| 整篇请求被截断：3209 字的稿子，录音停在第 3145 字（约 9050 字节），接口不报错 | 稿子（含标点、按朗读文本计）压到 **3000 字以内**再合成；合成后检查录音最后一句是否完整（逐字时间戳的最后一句 = 稿子最后一句） |
| 刘飞音色 + `speech_rate=25`：整篇实测约 6.2 字/秒，偏快 | 改用 **15**（整篇约 5.7 字/秒），再全篇 PSOLA 放慢 4%、讲数字的章节放慢 14% |
| 长录音的逐字时间戳在后半段“句首挤成一团”（十几个字挤在 0.06 秒里，比真实发声晚 1–1.5 秒） | 句界只用 DTW；**词锚点**用逐句参考音频自己的时间戳，经 DTW 路径映射到整篇录音上（与前段可靠的时间戳对比：中位误差约 0，90% 在 0.45 秒内） |
| 合成录音的停顿里有极轻的气声，按“峰值 −38 dB”找不到停顿 | 停顿阈值取“峰值 −24 dB”，能量曲线先做 55 ms 中值平滑，停顿至少 0.10 秒 |
| “巴菲特说：”这类 4 个字的短句，连读时比单念短，时长比只有 0.6 | 参考不到 1.5 秒的短句，时长比下限放宽到 0.55（DTW 距离仍须明显小于相邻句） |
| 整篇录音要入库、又要样本级一致（切点、词锚点都依赖它） | 录音存 **FLAC**（无损，约为 WAV 的三分之一），不要存 mp3 |
