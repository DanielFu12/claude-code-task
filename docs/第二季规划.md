## 二、第二季定位：护城河的另外几种样子

**入选标准**（用户已确认，和第一季护城河表用同一套）：
1. 护城河真实存在：能说清是哪一类，并拿数字或对手的实际反应作证据。
2. 对手很难长期复制：讲清原因。
3. 资本回报照样出色，或者至少能讲清回报为什么受限、为什么仍然值得持有。
4. 和伯克希尔有实质关系：全资拥有，或者长期重仓。

**补齐第一季没讲到的类型**：

| 类型 | 第一季 | 第二季 |
|---|---|---|
| 品牌和定价权 | 可口可乐、喜诗 | 不再专门做 |
| 网络效应 | 谷歌、美国运通 | 备选：Visa / 万事达（开放网络，和运通的闭环对照） |
| 低成本 | Costco | 内布拉斯加家具城（本地低成本）；GEICO（渠道低成本，难复制的原因不同） |
| 转换成本 | 苹果（讲得不透） | 精密铸件（航空认证）、怡安（企业保险经纪） |
| 技术领先 | 无 | 台积电（先进制程，和苹果呼应） |
| 有效规模 | 无 | BNSF（西部铁路双寡头） |
| 监管牌照或特许 | 无 | 穆迪（评级三巨头）、威瑞信（.com 独家运营） |
| 资本实力与信誉 | 无 | 伯克希尔再保险（只有它接得起的大单）、伯克希尔自己（收官） |

### 3.1 顺序与理由

整季按「从看得见的收费站，到看不见的信用」推进，最后收回到伯克希尔自己：

1. **特许与牌照**：穆迪 → 威瑞信
2. **重资产**：BNSF → 台积电
3. **买贵与买对**：精密铸件 → 内布拉斯加家具城
4. **保险发动机**：GEICO → 怡安 → 伯克希尔再保险
5. **收官**：伯克希尔自己

### 3.2 每期结尾的预告与承接（第二季起恢复，用户要求）

**做法**：
- 每期结尾留约 15–20 秒：先用一句话收住本期，再用一个问题引出下一期，配下一期的一个画面，加金色「下期」字样。
- 下一期开场的头一两句接住这个问题，再进入本期的冲突。
- 预告只说下一期要回答的问题，不剧透结论；预告里的事实同样要有出处。

| 本期结尾 → 下一期开场 | 承接点（暂定，写稿时再打磨） |
|---|---|
| 第一季美国运通 → S2E1 穆迪 | 第一季最后讲信任能做成生意。第二季开场：有一家公司，连「信用」都能打分收费 |
| 穆迪 → 威瑞信 | 穆迪的牌照靠监管和惯例；有一家公司的收费站，直接写在合同里 |
| 威瑞信 → BNSF | 互联网上的收费站讲完了；美国大地上，还有一条收费站：铁路 |
| BNSF → 台积电 | 同样是重资产、宽护城河，铁路他买下了全部，有一家芯片厂，他几个月就卖了 |
| 台积电 → 精密铸件 | 台积电是卖得快；下一家，是他承认买贵了 |
| 精密铸件 → 内布拉斯加家具城 | 370 亿美元的收购付贵了；有一笔收购，一页纸、没审计，却买对了 |
| 内布拉斯加家具城 → GEICO | 家具城的低成本靠一家人；还有一种低成本，靠绕开中间人，那是巴菲特 20 岁就去敲门的公司 |
| GEICO → 怡安 | GEICO 绕开了中间人；可大企业买保险，离不开中间人 |
| 怡安 → 伯克希尔再保险 | 怡安帮企业找保险；最大、最难的那张单子，最后找到的是伯克希尔 |
| 伯克希尔再保险 → 伯克希尔自己 | 别人敢把最大的风险交给它，这份信任从哪里来？ |
| 伯克希尔自己（收官） | 回看两季，不预告 |

**内布拉斯加家具城成片要补的改动**：开场加一句接住精密铸件，结尾加上 GEICO 的预告；第三章的低成本部分可以适当压短，把重点放到「怎么买、怎么看人」。

### 第二季开工前建议先做的两件事

1. **抽出公共模板**。现在每期都把上一期的 `src/` 整个复制一份，内布拉斯加家具城那期的修复（配乐 v4、TTS 3.0、清晰度、尾段核查）在旧期里并不存在。建议把通用部分放进根目录的 `engine/`，各期只保留 `script.py`、`gg.py`（镜头）、`media.py`（素材）和配乐提示。这样大约能省掉每期一天的搬运和返修。
2. **按期列素材清单**。内布拉斯加家具城那期的遗留问题是素材不够，有镜头循环重放。第二季每期写脚本前，先按章节估算需要多少秒素材，不够的那段在稿子阶段就调整。

## 五、每期节奏（参考内布拉斯加家具城那期的实际耗时）

1. 选题确认，用一句话写出核心问题。
2. 核实笔记（股东信、年报、公开采访），标明出处和口径。
3. 脚本，10–12 分钟。开场 1 分钟内要有冲突和悬念；每章回答一个问题；结尾给能带走的道理。
4. 素材：先审再用，记入 `ia_clips.json`。
5. 旁白合成 → 对齐 → 自检。
6. 时间线 → 配乐 → 混音。
7. 画面 → 抽帧审片 → 全片渲染（约 110 分钟）。
8. 成片、预览版、`SOURCES.md`，提交推送；向用户说明改动、新时间点和片长变化。
